# Полная онлайн-сборка

Рабочая публичная версия: [crocodile-bones.onrender.com](https://crocodile-bones.onrender.com/). Сайт и сервер комнат размещены вместе на бесплатном Render Web Service в регионе Frankfurt. Игрокам не нужен аккаунт Render или ChatGPT.

В проекте есть самостоятельный сервер Node.js. Он одновременно раздаёт готовую игру и синхронизирует комнаты. В браузерах друзей не требуется локальный сервер, VPN для соединения игроков или аккаунт в игре.

## Проверка готовой сборки

Нужен Node.js 22.13+:

```sh
npm ci
npm run build:node
npm start
```

Откройте `http://localhost:3000`. Это работает с готовыми файлами, без Vite. API и сайт находятся на одном адресе. Состояние сохраняется в SQLite; можно указать постоянный путь через `ROOM_DB_PATH`.

## Render

Файл `render.yaml` готов к созданию Web Service через Blueprint. Требуются подключённый аккаунт Render и доступ к репозиторию игры. В нём уже указаны сборка, запуск, проверка здоровья и бесплатный тариф.

Бесплатный Render выключает сервис после 15 минут без запросов. Первый вход после простоя может занять около минуты. Во время игры регулярные запросы игроков поддерживают работу сервиса. **На бесплатном тарифе локальная SQLite теряется при перезапуске сервиса**, поэтому незавершённые комнаты могут исчезнуть. Для сохранения комнат между перезапусками нужен постоянный диск с `ROOM_DB_PATH` на нём либо внешний постоянный хостинг. Сборка поддерживает постоянный диск, но его бесплатность не подразумевается.

Тариф и ограничения: https://render.com/docs/free

## Любой сервер с Docker

```sh
docker build -t crocodile-bones .
docker volume create crocodile-data
docker run -d --name crocodile-bones -p 3000:3000 -v crocodile-data:/data crocodile-bones
```

На публичном сервере настройте HTTPS через хостинг или обратный прокси. Том `crocodile-data` сохраняет комнаты между перезапусками контейнера.

## GitHub Pages

Можно отдельно разместить статический клиент на Pages. Для этого переменная репозитория `ROOM_SERVER_URL` должна содержать **фактический HTTPS-адрес опубликованного сервера**, без `/api`. Готовый workflow использует её во время сборки.

Публикация одного клиента на Pages без API не создаёт рабочую онлайн-игру. Размещение игры и API одним сервисом Render проще: отдельная настройка CORS и адреса API не нужна.
